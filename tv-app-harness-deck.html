Context 02 / 15

The Problem

Building a TV app from a content catalog today requires bespoke work per project. The same patterns repeat across every engagement:

Scaffolding

Monorepo setup, platform configs, Metro bundler, workspace management — every time from scratch.

TV-Specific UX

D-pad navigation, focus management, 10-foot UI spacing, spatial navigation trees — hard to get right.

Multi-Platform

Apple TV, Android TV, Fire TV (FOS + Vega), Web — each has quirks, manifests, and build paths.

Video player integration, CI/build setup, asset generation, theming — weeks of work that could be minutes.

Solution 03 / 15

A Harness, Not a Generator

The LLM provides intelligence — interpreting the brief, designing screens, writing component code.

The harness provides control — typed tools, deterministic scaffolding, a skill library, and a build/verify loop.

Thin harness Fat skills Deterministic tools

Core 08 / 15

The Orchestrator

Single class, single owner of session state. Holds the AppSpec, file tree, iteration counter, and budget.

class TVAppHarness {
  constructor(model, spec, workdir, config) {
    this.model = model;
    this.tools = new ToolRegistry();
    this.skills = new SkillLibrary("./skills");
    this.log = new RunLog(workdir);
  }

  async run() {
    this.skills.always_load("meta");
    for (const phase of PHASES) {
      this.skills.load_for(phase);
      await this.execute_phase(phase);
    }
  }
}

Responsibilities

  • Maintain tool registry + permission gate
  • Load SKILL.md files lazily per phase
  • Honor request_skill_load from agent
  • Honor write_auto_skill for new skills
  • Drive the 13-phase machine
  • Log every tool call (audit trail)
  • Recover from failures: error → next turn

Execution 11 / 15

13-Phase Build Loop

1Plan (→ AppSpec)schema validate 2Clone templategit + yarn 3Metadata & brandingtheme + assets 4Manifest wiringshape mismatch 5Screen customizationtypecheck + focus 6Navigation updateroute table 7Prebuild (Expo)native gen 8Static checkstsc + lint + focus 9Simulator buildbuild error 10Vega buildvega toolchain 11Visual & smoke testscreenshots + Maestro 12EAS build (optional).ipa / .apk 13Packagezip + report

Repair Pattern

On failure: collect {phase, tool, last_error, last_50_log_lines, relevant_file_excerpts} → next LLM turn with instruction "fix this, re-run." Cap at max_retries_per_phase.

Visual Check (Phase 11)

Maestro D-pad flow through every screen → PNGs → vision model: "Does this look like a working TV app screen?"
